# План миграции

Редизайн не требует переписывать ядро (`libs/`). Меняется только слой представления. Работы разбиты на этапы, каждый этап можно выпускать отдельно и откатывать.

## Этап 0. Токены (1–2 дня)

- Добавить `tokens/tokens.json` как источник правды в репозиторий.
- Сгенерировать из него `Color.kt`/`Type.kt` (Android) и `Theme.qml` (Qt).
- В `.gitignore` уже исключены артефакты сборки, генератор кладём в `tools/`.
- Критерий готовности: обе платформы собираются, приложение выглядит как раньше (тема подключена, но не применена).

## Этап 1. Android — тема и типографика (1 неделя)

Файлы: `android/app/src/main/res/values/colors.xml`, `styles.xml`, `android/app/src/main/java/app/organicmaps/…`.

1. Заменить палитру `colors.xml` на роли MD3. Старые имена оставить как алиасы на время миграции.
2. Перевести базовую тему с `Theme.MaterialComponents` на `Theme.Material3.DayNight.NoActionBar`.
3. Убрать `textAllCaps` у кнопок, выставить радиусы из `Shape.kt`.
4. Проверить тёмную тему (`values-night`), убрать хардкод цветов из layout-файлов.

Риск: кастомные вьюхи карты рисуют элементы своим кодом. Их палитра вынесена в `MapSymbols` и меняется отдельным коммитом.

### XML-ресурсы для старых экранов

Экраны на XML/Views могут использовать те же токены, что и Compose, без ожидания полной миграции:

- `android/app/src/main/res/values/colors.xml` — светлая схема;
- `android/app/src/main/res/values-night/colors.xml` — тёмная схема (Android выбирает её автоматически по системной теме).

Роли MD3 названы с префиксом `md3_` (`md3_primary`, `md3_on_surface`, `md3_surface_container_high`), цвета карты — с префиксом `map_` (`map_park`, `map_water`, `map_road_fill`, `map_route`). Оба файла являются зеркалом `tokens/tokens.json`.

```xml
<!-- layout -->
<TextView
    android:textColor="@color/md3_on_surface"
    android:background="@color/md3_surface_container" />
```

```kotlin
// Views / XML-экраны
val primary = ContextCompat.getColor(context, R.color.md3_primary)

// Compose рядом с XML-экранами
val primary = colorResource(R.color.md3_primary)
```

Можно продолжать использовать `MaterialTheme.colorScheme` в Compose и `@color/md3_*` в XML одновременно: значения совпадают, поэтому миграция идёт экран за экраном. Hex-значения в layout и drawable не хардкодим; при изменении `tokens/tokens.json` синхронизируем оба XML-файла и `Color.kt`.

## Этап 2. Android — навигация и нижний лист (2 недели)

1. Ввести `BottomNavigationView` с 5 пунктами и индикатором-пилюлей (`app:itemActiveIndicatorStyle`).
2. Перевести панели карты на `BottomSheetBehavior` с тремя состояниями (`peek`, `expanded`, `hidden`).
3. Заменить старые кнопки на FAB: primary 56, tonal 40.
4. Поисковую строку сделать отдельным `SearchBarView` (56 dp, радиус 28).

Порядок важен: навигация задаёт высоту контента, после неё подгоняются листы.

## Этап 3. Android — экраны (3 недели)

- Карточка места: Compose-экран или XML + `CollapsingToolbar`; карта-герой 320 dp.
- Поиск: список с карточкой лучшего результата.
- Настройки: `PreferenceFragmentCompat` с кастомными layout для сегментов и свитчей Material 3.
- Навигация: баннер манёвра + панель ETA.

Критерий: скриншот-тесты на 5 экранов в обеих темах, допуск 1 dp.

## Этап 4. Qt / desktop (1–2 недели)

- `qt/qml/Theme.qml` — singleton с токенами.
- Перевести `BottomSheet`, `Toolbar`, кнопки на новые свойства.
- Десктопная версия не копирует мобильную навигацию: нижняя панель заменяется боковой.

## Этап 6. Чистка

- Удалить старые алиасы цветов и неиспользуемые drawable.
- Обновить скриншоты в сторах.
- Прогнать проверку контраста по всем парам, зафиксировать в `docs/design-system.md`.

## Порядок и зависимости

```
Этап 0 → Этап 1 → Этап 2 → Этап 3
                 ↘ Этап 4 (независимо, после 0)
                 ↘ Этап 5 (независимо, после 0)
```

## Что не входит в объём

- Новые функции: офлайн-маршруты, синхронизация закладок, AR-навигация.
- Переработка отрисовки карты в ядре. Меняются только цвета символов через стили `data/styles/`.
- Локализация: новые строки добавляются сразу в `data/strings/strings.txt`, переводы — по обычному процессу.

## Критерии приёмки

1. Все пять экранов совпадают с прототипом по сетке, цветам и типографике.
2. Переключение светлой и тёмной темы не требует перезапуска.
3. Контраст текста ≥ 4.5:1, целей касания ≥ 48 dp.
4. Анимации отключаются системной настройкой «уменьшить движение».
5. Скриншот-тесты зелёные на Android и Qt.
